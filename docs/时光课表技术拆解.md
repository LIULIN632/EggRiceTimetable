## Part A. 课程块合并与渲染

### A1. 核心数据模型 `MergedCourseBlock`

定义：`ui/schedule/WeeklyScheduleViewModel.kt`（约 L37）

```kotlin
data class MergedCourseBlock(
    val day: Int,
    val startSection: Float,   // 逻辑节次偏移量：0.0 = 第一节课顶部
    val endSection: Float,     // 结束节次（含小数，支持自定义时间的比例定位）
    val courses: List<CourseWithWeeks>,
    val isConflict: Boolean = false,              // 本周有 ≥2 门课重叠
    val hasNonCurrentWeekCourses: Boolean = false,// 块内混有非本周课程（显示堆叠图标）
    val needsProportionalRendering: Boolean = false, // 含自定义时间课程 → 按比例渲染
    val isVisualDemoted: Boolean = false,         // 块内全是非本周课程 → 整块视觉降级
    val nonActiveRanges: List<Pair<Float, Float>> = emptyList() // 非本周区域的"纯区间"（供遮罩）
)
```

关键点：**坐标为 Float 逻辑刻度**（而非整数节次），因此能表达：
- 跨节次课程（3-4 节 = start 3.0, end 5.0）
- 自定义时间课程（按时间比例插值，见 A2）
- 课间休息产生的非整数偏移

### A2. 坐标归一化与边界处理（`mergeCourses` 前半段）

```kotlin
val minSafeHeight = 0.3f   // 最小可见块高，防止 1px 块
val limit = maxSection + 1.0f  // 课表绝对底部逻辑坐标

// 自定义时间 → 时间转逻辑刻度 timeToLogicalScale()
// 普通课程 → start to (end + 1f)   // 闭区间转开区间

// 边界吸附：
if (s >= limit) { e = limit; s = limit - minSafeHeight }   // 超出底部 → 吸附到底
else if (e <= 1.0f) { s = 1.0f; e = 1.0f + minSafeHeight } // 太靠顶 → 从 1.0 开始

// 高度不足 → 撑到 minSafeHeight
if (e - s < minSafeHeight) { ... }
// 最终 coerceIn 到 [1.0, limit-0.1] 防止越界
```

**`timeToLogicalScale(time, timeSlots)`**（L263）：把 LocalTime 映射为浮点逻辑坐标——
- 在第一节开始前 → 1.0
- 超过最后一节 → 底部
- 在某节时间内 → `slot.number + 已过分钟/该节时长`（比例插值）
- 课间 → 吸附到下一节起点

### A3. 贪心合并算法（重叠检测，L334-356）

```kotlin
// 按天分组，按 start 排序
var currentGroup = mutableListOf(sorted[0])
var currentMaxEnd = sorted[0].end
for (i in 1 until sorted.size) {
    val item = sorted[i]
    if (item.start < currentMaxEnd) {   // ← 重叠判定：起点 < 组内最大结束点
        currentGroup.add(item)
        currentMaxEnd = maxOf(currentMaxEnd, item.end)
    } else {
        result.add(createMergedBlock(day, currentGroup, ...))
        currentGroup = mutableListOf(item)
        currentMaxEnd = item.end
    }
}
```

要点：**顺次合并区间交叠的课程**。两个相邻但不相交的课程（如 1-2 节和 3-4 节）是独立的块；任何与组内并集区间相交的课程都会被并进同一块 → 一块内可能有 0 到 N 门本周课。

### A4. `createMergedBlock`：冲突与区间切割（L358-432）

排序：**本周课程优先，其次按 startSection**（保证本周课显示在上层/优先位）。

```kotlin
val isConflict = currentWeekCoursesCount > 1        // 本周 2+ 门 → 冲突
val isVisualDemoted = currentWeekCoursesCount == 0  // 本周 0 门 → 整块降级
val hasNonCurrentWeekCourses = 非本周课程存在 && 总数 > 1
```

**nonActiveRanges 区间减法**（遮罩关键算法，L389-419）：
1. 取非本周课程占据的原始区间 `nonActiveRawRanges`
2. 取本周课程占据的区间 `activeRanges`
3. 对每个非本周区间，用**每个**本周区间去"切割"它（区间差集）：
   - 无交集 → 保留原片段
   - 有交集 → 左侧保留 `[sStart, aStart]`、右侧保留 `[aEnd, sEnd]`
4. 得到**纯非本周区域**（本周课程覆盖的区域被剔除），UI 只在这些区域画遮罩

### A6. 配套机制（WeeklyScheduleViewModel）

- **三周滑动窗口预加载**（L116-155）：监听 `_pagerMondayDate`，同时拉取 `[前一周, 本周, 后一周]`，合并成 `Map<date, List<MergedCourseBlock>>` 缓存，ViewPager 左右滑零等待。

### A7. 移植到蛋炒饭课程表的建议

2. 先落地 A3 贪心合并 + 冲突判定（改造成本最低，收益最大——解决现在课程重叠互相挤压的问题）。
3. 再做 A5 的冲突条纹 + 重叠提示（两种模式）。
4. 进阶：nonActiveRanges 遮罩（单双周混排的课表里"本周不上"的区域变暗）——蛋炒饭有单双周，正好用得上。
5. 自定义时间课程比例渲染需要 A2 的 `timeToLogicalScale`。

## Part B. GitUpdater：延迟写入与版本校验

文件：`tool/GitUpdater.kt`（504 行，JGit + Wire protobuf）

### B1. 三阶段流水线总览（`updateRepository`，L437-503）

```
阶段一  updateResourceFiles  拉取/克隆资源仓库 → 只"暂存"文件清单（不写盘）
阶段二  downloadIndexFile    拉取索引分支 → 校验协议版本 + 数据版本 → 暂存内容
阶段三  commitUpdates        校验全部通过 → 清空本地仓库目录 → 统一写入
                            （索引版本未更新则恢复内存备份）
```

**致命错误立即终止且不写盘**：
- 资源文件拉取失败 → 终止
- 索引协议版本高于客户端（`isFatalIndexError`）→ 终止
- 远程索引版本**更旧**（数据回退异常）→ 终止
- 统一写入失败 → 报错（索引有内存备份可回滚）

### B2. 凭证与合法性验证

```kotlin
// 公开仓库免凭证；仅私有仓库/有 token 时提供
private fun createCredentialsProvider(repoInfo): CredentialsProvider? {
    // JGit Bug 修复：只有 token 没有用户名时 username 用 "x-token-auth"
    if (password.isNotBlank() && username.isBlank()) username = "x-token-auth"
}

// 基准灯塔标签验证：只查 tags，校验名称+SHA 精确匹配
private fun isLegitimateFork(userForkUrl, cred): Boolean {
    Git.lsRemoteRepository().setRemote(url).setTags(true).setHeads(false).call()
    // 要求远程存在 refs/tags/lighthouse 且 objectId == OFFICIAL_BASE_TAG_SHA
    // OFFICIAL_BASE_TAG_SHA = "eb49b7c18272c624d12198b03aabf7fc114a7106"
}
```

用途：**防止用户添加恶意/未验证的私有仓库**——只有基于官方仓库 fork（继承了官方灯塔标签）的仓库才被信任。正式版 `ENABLE_LIGHTHOUSE_VERIFICATION=true` 强制校验，开发版可跳过。

### B3. 阶段一：资源文件"暂存"（L141-245）

- 仓库克隆到 `cacheDir/temp_schools_repo`（已有则 `fetch + HARD reset` 到远程分支）
- 遍历 `resources/`，**跳过 `adapters.yaml`**（索引已含元数据，避免冗余）
- 每个文件记录 `Pair<临时文件, 目标文件路径>` 进 `result.resourceFiles`——**只暂存不写入**
- 用 `LogProgressMonitor` 输出 clone/fetch 进度

### B4. 阶段二：索引校验（L251-347）

索引独立成分支 `index-pb-release`（与资源分离：索引小、拉取快；资源大、单独更新），文件 `school_index.pb`（Wire protobuf 解码）。

```kotlin
// A. 协议版本：远程 > 客户端 → 致命（提示用户升级 App）
if (remoteProtocol > CLIENT_PROTOCOL_VERSION) {
    result.isFatalIndexError = true; return
}

// B. 数据版本：TIME_YYYYMMDDHHMMSS_XXX 时间戳字符串直接字典序比较
if (isNewerVersionId(remote, local)) {
    result.indexFileContent = sourceFile.readBytes()  // 暂存新内容
} else if (remote == local) {
    // 已最新，跳过写入
} else {
    // 远程更旧 → 致命！数据一致性保护（防远程仓库被回退/损坏）
    result.isFatalIndexError = true; return
}
```

容错：找不到索引分支 / 索引文件损坏 → 警告并继续（用本地旧索引），不阻断资源更新。

### B5. 阶段三：统一写入（L353-431）

```kotlin
// 1. 旧索引内容备份到内存（localIndexContent）
// 2. 整个 baseLocalDir deleteRecursively() 彻底清空
// 3. 重建目录 → 逐个 copyTo(overwrite=true) 写资源文件
// 4. 写索引：有新版 → writeBytes(新索引)；无新版 → 恢复内存备份的旧索引
```

**为什么先清空再写**：避免残留旧文件（仓库里已删除的文件不残留），且资源+索引在逻辑上同一版本。

### B6. 移植到蛋炒饭课程表的建议

蛋炒饭课程表目前"自动检查更新"只检查 App 版本；可扩展为**适配数据热更新**：

1. **最简版**：GitHub Actions 把 `school_registry` 数据编译成索引（JSON 或 protobuf），App 检查更新时拉索引 → 增量更新学校列表（比 JGit 轻量，纯 OkHttp 即可，符合"OkHttp 优先"约束）。
2. **完整版**：照抄三阶段流水线——`暂存 → 校验（协议版本 + 时间戳版本 + 回退保护）→ 统一写入`，重点是：
   - 版本号用 `TIME_YYYYMMDDHHMMSS_XXX` 时间戳，字典序比较
   - 远程比本地旧 = 数据异常，拒绝写入（防回退）
   - 写入前备份旧文件到内存，失败可回滚
   - 协议版本字段，防止新索引与旧 App 不兼容
3. **安全**：若开放自定义仓库，用"灯塔标签"式校验（ls-remote 查官方基准 tag 的 SHA）。
4. 不要引入 JGit 到蛋炒饭课程表（体积大）；用 OkHttp 拉 zip/tar 或单文件索引即可，但**校验/延迟写入/回滚的逻辑照抄**。
